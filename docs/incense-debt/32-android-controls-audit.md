# Android 键位、移动端适配审查与优化方案

日期：2026-10-09。对象：《香火债》0.2.0 当前源码与 Android 交付记录。

当前触控系统已经具备双摇杆、多指独立捕获、布局编辑、瞄准辅助、后台暂停和方向保护，但交互仍主要沿用桌面画布和动作分配。最需要解决的是双拇指的动作争用、编辑位置与实际输入区域不一致、开火与瞄准阈值矛盾，以及触控尺寸和流程入口缺乏统一约束。

本篇保存 0.2.0 的问题审查和设计提案；当时尚未把提案写入游戏或重新生成 APK。随后按用户追加要求完成 0.2.1 修订，当前实现、实机图及新版包体验证见 [33 动作与移动操作修订](33-action-mobile-update.md)。本篇下方图中的推荐侧是原布局示意，并非新版本实机截图。

P1：优先处理，直接影响操作可靠性或触屏功能闭环。P2：随后处理，影响理解、比较、可达性与适配品质。以下“复现”均指原生软件输入，不是真机手感结论。

### 尺寸推演的实际含义

以 1080 像素高、密度参数 480、场景缩放 1.5 的假设设备为例，48dp 需要 96 个当前逻辑单位；90 的上限只得到 45dp。固定 50 单位按钮约 25dp，48 单位按钮约 24dp。这是当前公式的算术反例，不能解读成已测量某款手机；Android 逻辑 density 与物理 DPI 也可能不同，不能用桌面 DPI 验收手机。

Android 官方建议触控范围至少 48×48dp，相邻目标留 8dp 或更多间距：[Android 触控目标尺寸](https://support.google.com/accessibility/android/answer/7101858?hl=en)。Godot 的 keep 会把宽屏余量变成引擎黑边，不能直接在这些黑边中绘制按钮：[多分辨率说明](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)。因此需要调整根界面布局架构，而不能只移动现有画布内几个坐标。

## 推荐方案：保留方向操作，改为双拇指优先

推荐保留双摇杆和轻度辅助，维持肉鸽的主动走位与方向控制。自动瞄准作为可选辅助，右手手动拖动时优先响应玩家；不把双击、复杂划线或强制三指当作完成基础操作的要求。

| 区域／动作 | 推荐行为 | 关键实现约束 |
| --- | --- | --- |
| 左下移动杆 | 在限定下方区域内浮动，支持固定模式。 | 固定／浮动都有明确起始区域；捕获后出区仍跟踪，直到抬起或取消。 |
| 移动杆内上侧身法 | 左拇指短距离切换。 | 按下时取得近期移动方向作为 `dash_direction`；没有移动意图再采用瞄准方向，避免抬起左杆后向敌人方向错误闪避。 |
| 右下瞄准／射击杆 | 与左杆形成接近对称的握持布局；推动瞄准并攻击。 | 瞄准有效后才开火。保留最后朝向；开火与停止有不同阈值，不能在死区内用旧朝向射击。 |
| 右杆内上侧焚债 | 在短拇指行程内按下，使用最后有效瞄准。 | 标记／香火／冷却一起决定可用态；动作切换短时保留蓄力进度，不额外自动开火。 |
| 右杆内侧道具 | 装备后显示，低频操作占次级位置。 | 充能与失效原因直显；没有道具时不接收此区域动作。 |
| 地图与暂停 | 点击顶部章节查看只读地图；暂停保留本局记录／构筑。 | 打开后清空攻击捕获并停住模拟，关闭后等待新的操作；地图不承担普通房间传送。 |
| 情境交互 | 靠近掉落／入口时，在操作区附近显示一个交互键与简短预览。 | 显示前后装备差异；从已有交互类型选定唯一目标，不让拾取与攻击热区叠盖。 |

左侧身法的作用是让右手能继续控制方向与射击意图；World 当前在身法动作期间有自己的射击限制，这属于战斗规则，提案不承诺闪避动画中仍不断出弹。技能按键也不应导致永久自动射击或无限保留蓄力。

蓄力建议：保留当前“持续输入直到完成”的武器行为；由技能按钮切换造成的短暂射击释放可以保留约 100～150ms 的蓄力进度，返回瞄准杆后接续。普通松手、离开操作、暂停、切房、进入菜单都停止攻击；不接回输入就取消蓄力。保留窗口内不增加进度、不替玩家发射。若以后另做“松手发射”，应按武器单独定义，不能把现有蓄力武器整体改掉。

### 不同武器采用不同输入说明与辅助

| 武器类型 | 移动端操作与表现 |
| --- | --- |
| 普通弹／三发散射 | 推杆即按当前方向射击，轻度吸附保留方向自由；显示扇形范围即可。 |
| 近战／蓄力斩 | 保持朝向，清楚显示挥击弧；只在前方范围内辅助，避开向身后突然改向。 |
| 蓄力卷／判官笔 | 摇杆边缘显示蓄力环；区分主动松手与按技能的短时切换，阈值抖动不反复丢失进度。 |
| 射线 | 连续方向输入决定束线；降低吸附强度，避免在近距离小怪间来回跳转。 |
| 引魂纸蝶／可控弹 | 存活弹存在时右杆优先负责转向；允许配置“只操控／继续发射”，手动引导期间暂停自动抢目标。 |
| 范围／延时爆炸 | 使用清楚的范围圈和落点预览；未来需要指定地点时支持拖动瞄准，拖入取消区即可取消。 |

## 移动界面与适配原则

战斗保留当前纸偶、场景、资源圆体／得意黑、深灰胶囊、玉青与杏橙。常驻文字只保留必要数值与章节；技能使用真实图案，冷却和蓄力用环形表达。把完整供物列表收进暂停构筑页，减少拇指区域的常驻图标。两种模式间切换时，按钮位置保持稳定，隐藏的按钮同时停用热区。

选技能／供物：3 个候选默认同屏，4 个也保留同屏缩略入口；点候选只切换选中和详情，点单一确认键才提交。复杂描述在独立可滚动详情区展开。献灯、判官、偿债等显示心火／纸钱图标与准确代价，破坏性选择增加明确确认；普通免费奖励保持快速单次确认。重掷按钮必须显示次数或价格。小屏空间不足时保留全部候选缩略入口，不能退回只有前后翻页、需要背选项的方式。

适配从布局计算开始统一：

- 根界面支持完整屏幕比例；战场继续按独立 16:9 矩形居中，用明确变换保持 1280×720 模拟坐标。触控与 HUD 在独立全屏 CanvasLayer 中按安全区下角／上边锚定。宽屏侧边可沿用场景边框装饰，不拉宽角色或改变房间碰撞。
- 使用 Android 逻辑密度换算触点，而不是把项目像素直接当成 dp。动作键建议 52～60dp，最小有效热区 48dp；杆盘约 80～104dp；间距 8～12dp，额外留出系统手势边缘。空间不足时调整间距、次级控件显隐或布局，不用固定 90 上限把必要热区缩小。
- 布局改为安全区锚点、容器和设备类别规则，统一作用于教学、播片、替换、设置、结果、信息按钮。正文保留当前字体，同时设置可读的基准尺寸和界面字号档，不能只放大故事与战斗弹字。
- 提供左右手镜像、小屏手机、宽屏手机和平板预设；编辑器增加真实安全区、热区、重叠提示和立即试操作。镜像时动作含义与区域一起镜像。
- 横屏适配允许两种横向握持方向；更换尺寸、折叠／展开与安全区变化时重新排布并清空已有捕获，必要时保留暂停确认。现有方向保护和后台存档继续作为基础。

## 实施顺序与验收

第一批先统一 TouchLayout 与动作状态，修复跨半屏布局、死区／开火、固定模式捕获、清房隐形按键，补战斗地图按钮。随后让视觉、命中区域、编辑器和镜像共享同一份数据，并把可施放条件接到按钮。

第二批实现左侧身法和右侧动作分布，以及稳定的蓄力切换、武器辅助策略；先用现有训练房实际操作，再固定默认位置。第三批统一全屏安全区与 dp 热区，覆盖小按钮和菜单；最后调整同屏选卡、情境交互、教学和手机设置入口。

验收应包含：不借键盘完成一整局及所有可达菜单；普通／散射／近战／蓄力／射线／可控弹逐类操作；双拇指移动与身法／焚债组合；编辑后每个触点动作正确；看得见且可用的控件都有相符反馈；不同阶段不存在隐形热区；暂停、切房、后台、系统返回后没有残留输入；地图仍按实际走门推进。

至少覆盖 16:9、18:9、20:9、4:3、左右横向、刘海与手势导航、最小可用窗口、输入法展开、低帧率压力和外设接入。物理触控尺寸、长局热表现与输入取消以当前 APK 的真机记录为准；最终 APK 哈希必须与验收记录一致。

触摸事件取消字段的语义参考 [Godot InputEventScreenTouch](https://docs.godotengine.org/en/stable/classes/class_inputeventscreentouch.html)。当前普通释放已经正确清理，未观察到实际手机取消事件，因此这里是待验证的边界，不是已经证实的“后台后卡住”故障。
