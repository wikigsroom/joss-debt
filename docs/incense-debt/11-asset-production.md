# 素材说明、生成计划与导入流程

## 素材来源与状态

生成的栅格美术统一使用用户指定 `sub2-image-gen` 和 `gpt-image-2.5`。原始图保存在项目 `output/imagegen/incense-debt/`，提示词、模型、尺寸、文件哈希与检查结果登记在清单。布局、线框、游戏逻辑和图表使用原生代码制作。

当前角色板和首区环境板为 `reviewed_concept`，表示已检查视觉方向；`planned` 是有规格待制作；`normalized` 表示已裁切/透明/锚点处理；`engine_verified` 需要引擎运行截图与动画检查。只有最后一类可计入正式交付素材。

## 类别和尺寸

| 类别 | 正式显示/帧尺寸 | 原始画布策略 | 透明与锚点 |
| --- | --- | --- | --- |
| 主角六状态 | 96×96 | 256单元、四方向分行、一次整条/整板生成 | 真alpha；(0.5,0.84)脚点 |
| 普通敌人动作组 | 128×128，显示64–128 | 同一敌人整组生成并规范 | 真alpha；脚点统一 |
| Boss 动作/部件组 | 256×256起，按部件拆层 | 身体、铜印、账页分别生成 | 透明；部件连接点登记 |
| 武器 | 96×96 | 统一握点、基础朝右；由引擎旋转 | 透明；握点独立于图心 |
| 遗物 | 64×64 | 一图一个主形；可批量成板后逐格检查 | 透明；中心 |
| 技能与路线图标 | 64×64 / 48×48 | 共用路线外框，技能主形区分 | 透明；中心 |

| 墙/角 | 128×128 | 对齐64单位网格的顶面与立面 | 透明；网格碰撞分开 |

世界单位和纹理像素分别定义。角色命中圆独立于美术宽度，伞灵的伞缘和傩面的肩甲不会偷偷扩大判定。

## 动画清单

每角色至少：待机4帧、移动6、焚债4、身法3、受伤2、死亡5，四方向。一个角色状态统一缩放，不对每帧独立撑满画布；握点和脚点用同一标尺校正。

敌人至少待机、移动、前摇、攻击、受伤、死亡；每敌记录哪些状态可通过拆层形变复用。Boss至少待机、三类主要攻击、阶段转换、受伤与死亡，关键预警部件独立层。

武器从角色本体拆出，避免六角色×十六武器的整套动画组合爆炸。角色身上的手位提供武器挂点，武器摇摆和射击后坐由程序动画配合；铃师双铃和伞灵伞面作为角色关键层另行保留。

## 实际生产顺序

1. 锁定纸童的一个正式待机帧，检查96像素轮廓、色板和alpha；以它作为同角色动画的统一基准。
2. 在一次生成请求中描述完整动作条，明确帧数、方向、服装、比例、画格和背景；不逐帧随机生成独立人物。
3. 校正背景、尺寸、共享比例、脚点与空白边；保留原图及处理参数。
4. 生成预览条，在引擎中播放待机、移动、施放、受伤，确认与命中体积相配。
5. 通过纸童后扩展铃师和灯客，再补其他角色。环境从首区地面、墙、门开始，随后加入低频道具。
6. 首个切片完成后再扩展铜钱库、无主神殿、遗物图标和剩余敌人；所有新增图沿相同基准检查。

生成失败时保留网关错误与状态，不静默换模型。凭据留在技能本地配置，不进入提示词、项目清单、日志或游戏包体。整个生产运行在本机与指定HTTP网关，不依赖虚拟化环境。

已验证本地CLI的 `edit --image` 参考图入口。角色以原六人设定板为外形基准，首区以选定方向图和环境板为地图基准，调用同一 Sub2API 网关重绘，再进行规范化和引擎检查。`generate` 入口仍用于没有已有基准的新素材。网关返回并发限制时按原模型重试；不切换供应商或用文本重新解释已锁定的造型。

现已接入六角色四朝向的参考图重绘、首区参考图重绘、原角色板的直接肖像裁切，以及原环境板中的道具裁切。当前动作使用锁定朝向图配合程序纸偶形变；这不等于已经完成上表全部逐帧动画。运行资源的来源和处理参数记录在 `game/assets/runtime-manifest.json`。

## 可复制提示词骨架

“原创《香火债》正式2D游戏素材；主体=[稳定ID与明确轮廓]；近俯视且面部可读；粗墨外轮廓、纸纤维边、两三档平涂；朱砂/煤墨/纸白/旧金/灰玉；左上同一光源、短影；[帧数与单元布局]；同一角色、同一衣物和武器、共享大小与脚点；真透明背景；无文字、无场景、无多余角色。”

针对环境，替换为可平铺地面或模块物，明确网格、连接边、碰撞参考和装饰强度；针对VFX，明确“友方圆火片”或“敌方尖核”，不得混用。

主角与环境完整提示词已在 `assets/prompts/`；正式生产提示词库将按照角色、武器、敌人、Boss、环境、遗物、VFX、UI分类维护。

## 导入与内存

图集以角色、区域、UI分类，移动端单张纹理优先不超过2048×2048。纸童动作采用统一双线性缩放与保边处理，具体压缩设置经移动端透明边缘测试确定。按房间/区域预加载，进入下一层后释放上层非共用纹理。

纹理、音效与运行内存分别记账；目标纹理驻留预算128MB、工作集350MB、包体180MB，为设计预算，需实际设备测量证明。原始高分辨率生成图不进入正式游戏包。

## 逐项验收

清单 ID 与数据库引用存在；尺寸和alpha正确；图集切片数正确；没有文字、水印、重复人物或透明白边；帧间颜色、头身比例、脚点和握点稳定；实际尺寸能区分角色与状态；上/下/左右动作方向一致；引擎里无闪边与越界；生成元数据与正式导入资源路径可追溯。
